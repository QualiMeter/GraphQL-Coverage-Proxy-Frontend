# Проверка локального frontend с production API

Дата: 2026-11-16. Backend: https://graphql.rebyte.fun. Frontend:
http://localhost:5173. Локальный backend и PostgreSQL не запускались.

## Автоматические проверки

Node.js 22, зависимости из lockfile:

- `npm run lint` — успешно.
- `COVERAGE_DEV_PROXY_PRODUCTION_AUTH=true npm test` — 15 файлов, 113 тестов успешно.
- `COVERAGE_DEV_PROXY_PRODUCTION_AUTH=true npm run build` — успешно; `/coverage/` сохранён.
- В `dist` нет флага и реализации привилегированного proxy.
- Сборка предупреждает о существующем JS chunk >500 kB.

Тесты proxy проверяют точный локальный Origin, чужой/отсутствующий/null Origin,
другой порт, cross-site/same-site Fetch Metadata, Host и loopback, запрет
небезопасных настроек CLI, отключённый флаг, build и preview. Реальные HTTP-запросы
к одноразовому upstream в памяти подтверждают передачу Cookie, Set-Cookie,
CSRF и дополнительных заголовков без изменения cookie. Отдельно проверены
восстановление operator/admin сессий и отсутствие повторов изменяющих запросов.
Автотесты не обращаются к production и не изменяют БД.

## Ручная проверка production

Использован предоставленный пользователем отдельный тестовый оператор. Пароль,
значения cookie и CSRF не сохранены в репозитории или отчёте.

| Проверка через localhost proxy | Результат |
| --- | --- |
| GET /api/services без сессии | 200 |
| GET /api/auth/users без сессии | 401 |
| POST /api/auth/login | 200, operator |
| GET /api/auth/session после входа | 200, текущий operator |
| GET /api/services с сессией | 200, один доступный сервис |
| GET /api/schemas?serviceId=… | 200 |
| GET /api/schemas/{id}/graph | 200 |
| GET /api/auth/users под оператором | 403 |
| POST /api/auth/logout без CSRF | 403 |
| POST /api/auth/logout с неверным CSRF | 403 |
| Сессия после отклонённых logout | Сохранилась |
| POST /api/auth/logout с верным CSRF | 204 |
| GET /api/auth/session после logout со старой cookie | 200, user=null |

Встроенный браузер Codex: выполнен вход из UI, после обновления страницы аккаунт
восстановлен, в меню отображается роль «Оператор». Выбран реальный сервис,
отображены снимок и граф (3 типа, 10 полей). Выполнен выход из UI, после обновления
страницы доступна кнопка входа. Предупреждений и ошибок в консоли не обнаружено;
сессия сохранялась без повторного ввода пароля. Браузер принял Secure
`__Host-coverage_session` на HTTP localhost. Атрибуты Secure, HttpOnly,
SameSite=Lax и Path=/ сохранены.

HTTP-проверки прав/CSRF выполнены отдельным клиентом с cookie только в памяти;
браузерная проверка отдельно подтверждает принятие Secure cookie, перезагрузку и
UI logout. Оба созданных тестовых сеанса завершены. Бизнес-данные не менялись;
в production создавались/удалялись только сессии тестового оператора и штатные
данные механизма входа. PostgreSQL напрямую не инспектировалась: проверены ответы
реального production API.

## Ограничения

- Реальный вход администратора не выполнялся: предоставлен только аккаунт
  оператора. Роль admin уже поддерживается общим контрактом авторизации;
  login и восстановление admin сессии покрыты автоматическими тестами.
- Совместимость Secure и `__Host-` cookie на HTTP localhost зависит от браузера,
  версии и политик профиля. Проверен встроенный браузер Codex; остальные браузеры
  не проверялись. При блокировке используйте совместимый браузер или production
  frontend по HTTPS, сохраняя защитные атрибуты cookie.
- Cookie localhost общие для портов; нужен отдельный профиль. Не публикуйте
  dev server через LAN, reverse proxy, туннели или port forwarding.
- Запись бизнес-данных не проверялась: согласованные ресурсы для таких изменений
  не предоставлены. Отклоняемый logout проверяет CSRF без изменения рабочих данных.
- Существующий frontend получает каталог, снимки, граф и SDL; production прогоны,
  операции и обращения пока не подключены. Этот PR меняет подключение и
  авторизацию, а не добавляет отсутствующие API-экраны.
- Production backend, cookie, CSRF, роли и настройки безопасности не изменены.
  Деплой и merge не выполнялись.
