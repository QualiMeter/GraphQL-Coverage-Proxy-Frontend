# Сравнение прогонов — отчёт

Реализация оставлена локально в `feat/frontend-dashboard`. Предыдущие изменения удаления Mock-режима сохранены. Коммиты, операции записи в GitHub, изменения backend, `.env.local`, production-инфраструктуры и CI/CD не выполнялись. Production-прогоны не создавались и не изменялись.

## Контракты

Изучены `app/api.py`, `app/api_models.py`, `app/run_comparison.py`, `app/run_analytics.py`, `app/journal.py`, `app/test_coverage_api.py`, `app/test_executions.py`, `app/evidence_analytics.py` в [backend-репозитории](https://github.com/QualiMeter/GraphQL-Coverage-Proxy-Beckend/tree/main/app).

Прочитана [production OpenAPI](https://graphql.rebyte.fun/openapi.json). В ней присутствуют `/api/runs/compare`, `/field-evidence`, `/tests`, подробности попыток и поля попыток. Несовместимости изученных DTO с репозиторием не обнаружены. `comparisonDtos.ts` и `comparisonSchemas.ts` сформированы из production OpenAPI от 18 ноября 2026 года; вложенные adjacent-переходы дополнительно проверяются по реализации `run_comparison.py`.

Сравнение — аналитический POST с существующими same-origin cookie, Origin через текущий Vite proxy и CSRF при наличии сессии. Автоматических повторов после ошибки нет. Повтор выполняется только по действию пользователя. Backend остаётся окончательным источником проверки полноты GitLab-сбора.

## Реализовано

- Кнопка «Сравнить прогоны» в истории; самостоятельное представление с возвратом в историю и разделами «Обзор / Поля / Типы / Исследование». Новая основная вкладка не добавляется. Сводка одиночного прогона на странице сравнения не отображается.
- Пагинированная история завершённых прогонов выбранного снимка. Предлагаются два последних завершённых прогона; их дополнительная совместимость по полноте GitLab-сбора проверяется сервером. Выбор 2–20 без повторов, baseline/target, удаление выбранных прогонов, хронологическая последовательность. Смена снимка сбрасывает выбор. Изменение выбора убирает старые результаты до нового запроса.
- Основные показатели baseline/target и серверные дельты. Нейтральная оценка роста обращений, отрицательная оценка роста ошибок. Неизвестные длительности сохраняются как `null` и показываются прочерком.
- SVG-график покрытия, обращений, HTTP/GraphQL-ошибок, средней длительности и P95. Табличные подписи содержат все значения. Соседние изменения берутся из `adjacentCoverageDeltasPp`, порядок — из `runs[]` backend. Дополнительные сведения Query/Mutation/Subscription и статусов анализатора раскрываются отдельно.
- Все девять фильтров полей, серверная пагинация по 50; первоначально выделяется потеря покрытия. Hits baseline/target, частота, переходы, стабильность, раскрываемая история покрытия и выбор соседнего перехода.
- Пагинированные типы, root role, число полей, baseline/target, изменение и раскрываемые значения каждого прогона. Переход к полям типа. Контракт сравнения не поддерживает серверный фильтр `typeName`: ограничение типа применяется к текущей странице общего списка, это явно объясняется в интерфейсе; остальные страницы доступны пагинацией. Массовая загрузка полей не выполняется.
- Исследование произвольной пары из выбранной последовательности без потери общего сравнения. Операции загружаются только для двух выбранных прогонов. Сопоставление исключительно по operationKey; разные ключи с одинаковым именем/типом предлагаются как кандидаты, без утверждения эквивалентности. Операции с учтёнными hits поля показываются первыми, остальные доступны отдельно.
- Отдельные обращения по полю или выбранной операции с пагинацией; подробности только по выбору пользователя. Диагностика analysisStatus, responseHasData, countedInCoverage, HTTP, GraphQL и безопасных подробностей ошибок. Неизвестная идентичность не синтезируется.
- Два реальных safeGraphqlDocument рядом, подсветка различий строк; недоступный документ не заменяется пустым кодом. При redacted показано сообщение о маскировании сервером. Повторное исполнение документов не предусмотрено.
- Field Evidence по запросу пользователя для выбранной пары: успешный выбор, selectedHits, observedHits, notObserved/indeterminate/unavailable и общие показатели недоступности выбора/evidence. Неизвестное состояние не объявляется отсутствием поля. Неучтённые обращения не объявляются ошибочными без диагностики.
- Test Coverage с covered/selected/observed, отдельной пагинацией сторон, сопоставлением framework + testId и сохранением каждой attempt. Подробности выбранной попытки и её полей загружаются отдельно. Отсутствие попытки на текущей странице/с данным фильтром не объявляется доказательством того, что тест не запускался.
- Блоки загрузки/ошибок и ручного повтора независимы. Отмена запросов и проверка ключа контекста не позволяют показать прежнюю пару после переключения. Смена ревизии сессии перемонтирует страницу. Ошибки 401/403 не заменяются пустыми результатами; отсутствие роли ограничивает только защищённые подробности.
- Используются существующие CSS-переменные, светлая/тёмная темы, адаптивная двухколоночная компоновка и внутренний скролл широких таблиц.

## Проверки

- `npm run lint`: успешно.
- `npm test`: 23 файла, 212 тестов успешно; из них 34 новые проверки.
- `npm run build`: успешно. Сохраняется предупреждение Vite о JS-файле больше 500 kB.
- Unit-тесты проверяют ограничения 2–20, snapshots, дубли, статусы, baseline/target, POST и CSRF, DTO, фильтры, пагинацию, несовместимость и отсутствие автоматических повторов, evidence-счётчики, права, неизвестные документы, operationKey, кандидатов, повторные попытки, динамику, переходы и защиту от прежнего контекста.

Браузер на настоящем backend: открыты история и новая страница, загружен completed-only список, проверен запрет сравнения при одном завершённом прогоне. Проверены светлая и тёмная темы и возврат к истории с восстановлением обычной сводки. На viewport 390×844 горизонтального переполнения страницы нет (scrollWidth=390), элементы выбора читаемы. Временное изменение темы и размера viewport отменено.

## Что не подтверждено на реальных данных

В доступном анонимному пользователю Frontend Demo Shop только один завершённый прогон; второй имеет статус running. Поэтому настоящий успешный POST сравнения двух прогонов и заполненные результаты сравнения в браузере не проверены. Production-прогоны ради проверки не изменялись; POST сравнения с фиктивными данными не отправлялся.

Не выполнена браузерная проверка выборок 3–20 реальных прогонов, серверного отказа из-за GitLab-сбора, заполненных операций/документов с различиями, авторизованных журналов, Field Evidence и зарегистрированных тестовых попыток. Эти пути реализованы и проверены на контрактах/unit-тестах, но требуют окончательного прохода на доступных завершённых прогонах и учётной записи с нужными правами. Проверка адаптивности заполненных исследовательских таблиц и всех сценариев существующего приложения также не является полной.
