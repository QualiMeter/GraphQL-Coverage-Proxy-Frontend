# Подробности обращения и GraphQL Error Details

## Изменения интерфейса

Правая панель существующего журнала теперь имеет компактный закреплённый заголовок: имя операции или «Безымянная операция», Query/Mutation/Subscription, дата/время и закрытие. Прокручивается тело, поэтому закрытие остаётся доступным. Длинные имена переносятся и ограничены по высоте.

Содержимое организовано в согласованном порядке:

1. Три небольших показателя HTTP / GraphQL / длительность.
2. Общая диагностика GraphQL-ошибок.
3. Существующий безопасный документ через CodeView с копированием и разворачиванием.
4. Раскрытие «Поля и доказательства» с единственным прежним списком selectedFields и Field Evidence.
5. Компактный «Связанный E2E-тест» с сохранённым переходом к конкретной попытке.
6. «Дополнительные сведения»: HTTP-метод, локальный анализ, его errorCode, responseHasData, countedInCoverage, ID и прежнее действие открытия операции.

HTTP, upstream GraphQL-ошибки и локальные ошибки анализатора не объединяются. HTTP 200 может сочетаться с GraphQL-ошибками. Учёт в покрытии не интерпретируется как отсутствие ошибок. Исходные критерии покрытия и Evidence не изменены.

## Диагностика

GraphqlErrorDetails используется и в основной панели, и в компактном виде в ComparisonInvestigation. Подтверждённые ошибки раскрыты по умолчанию. Путь форматируется только из переданных сегментов (`customer.orders[0].id`), без реконструкции из документа. Неизвестный путь — «Путь не подтверждён», null safeMessage — «Сообщение недоступно».

Подтверждённый count=0 занимает одну короткую строку. Null/отсутствующий count остаётся неизвестным даже при старом graphqlHasErrors=false. Unavailable оформлен нейтрально. Truncated показывает полный известный count и число доступных записей, с пояснением возможного сокращения списка, путей и позиций, даже если все записи присутствуют. Если общий count неизвестен, он не заменяется количеством доступных деталей.

Позиции показываются текстом как исходные line/column; привязки к строкам отформатированного/редактированного безопасного документа нет. Raw message, extensions, исходные тела и скрытые значения не используются. React выводит значения как текст. Отсутствующий код ошибки нейтрален; известные ошибки и HTTP failures имеют текст и цвет, а неизвестные сведения не получают ложный статус успеха.

## API

Используется прежний GET `/api/runs/{runId}/requests/{requestId}`. Новых endpoint или запросов для каждой строки журнала нет. Основной RequestDetail расширен существующими полями graphqlErrorCount/graphqlErrorDetailsAvailability/graphqlErrorDetails; типы comparisonDtos и metadata comparisonSchemas уже содержали эти поля и сохранены.

В обоих клиентах деталей применяется общий валидатор: состояния availability, nullable-поля, целый count в backend-диапазоне, до 20 записей и 16 КиБ JSON, до 16 сегментов пути и 8 позиций, допустимые индексы и координаты. Старые ответы без новых полей поддерживаются. Контекстные ключи деталей включают scope/run/snapshot/request/revision/retry; старые HTTP-ответы не подменяют текущий выбор. Добавлено повторное чтение при ошибке деталей.

Для поля и теста сохраняются прежние GET Field Evidence и Test Execution. Их загрузчики и навигация переиспользованы. Поля и Evidence не дублируются, семантика четырёх состояний не меняется.

Read-only проверен актуальный backend-контракт [docs/graphql-error-details.md](https://github.com/QualiMeter/GraphQL-Coverage-Proxy-Beckend/blob/main/docs/graphql-error-details.md).
