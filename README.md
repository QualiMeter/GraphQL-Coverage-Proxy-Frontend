# GraphQL Coverage Proxy

Локальная аналитика наблюдаемого использования полей GraphQL. Покрытие не доказывает корректность значений в тестах.

## Запуск

```bash
npm install
npm run dev
```

Приложение открывается по адресу Vite, обычно `http://localhost:5173`. Проверки: `npm run build`, `npm run lint`, `npm test`.

## Возможности

- Схема и покрытие: React Flow с портами отдельных полей, таблица, фильтры, детали типов и полей.
- Операции: группировка по идентификатору структуры, частота, ошибки, длительность, затронутые поля, безопасный GraphQL-код.
- Обращения: журнал с фильтрами HTTP, GraphQL, анализатора, операции и поля; подробности и код.
- История прогонов: выбор исторического прогона переключает общий snapshot и все показатели.
- Для Mock Customer API доступны создание прогона, завершение прогона, импорт `.graphql`/`.gql` через GraphQL-парсер. Локальные записи сохраняются в `localStorage` этого браузера.

Mock Customer API использует локальные снимки, прогоны и детерминированные обращения Customer. Сценарий Billing остаётся в тестовых данных. Метрики, операции, журнал и покрытие вычисляются из одних записей. Отдельный контрольный набор Query/User/Order проверяет 5/9 и 6/9.

## Архитектура и интеграция

`src/analytics/model.ts` содержит типы и расчёты, `fixtures.ts` — связанные локальные данные, `sdl.ts` — импорт схем, `storage.ts` — локальное хранение. Граф использует `src/graph/transform.ts` и `TypeNode.tsx`.

Селектор объединяет локальный Mock Customer API и сервисы из `GET /api/services`.
Анонимный запрос получает публичные сервисы. С действующей сессией сервер учитывает
роль и права на конкретные сервисы. Ошибка загрузки отображается в селекторе, где
запрос можно повторить. При выборе сервиса API загружаются его снимки и граф выбранного снимка.
Вкладка SDL читает сохранённую схему отдельно. Граф показывает структуру без
метрик покрытия до подключения прогонов. Прогоны, операции и обращения API
пока не подключены.

- Vite проксирует `/api/` на `https://graphql.rebyte.fun` по умолчанию. Клиент использует относительные пути и `credentials: 'same-origin'`.
- Для разработки cookie-авторизации скопируйте `.env.example` в `.env.local` и задайте `COVERAGE_API_PROXY_TARGET=http://localhost:8000`. На локальном backend требуются `COVERAGE_DEV_MODE=true` и `COVERAGE_PUBLIC_ORIGIN=http://localhost:5173` (точный origin приложения). Production проверяет собственный Origin. Прокси его не переписывает.
- В production разместите frontend и `/api/` на одном origin. Ключ API и другие секреты остаются на сервере или в доверенном CLI. CSRF-токен хранится в памяти и передаётся в заголовке `X-CSRF-Token` при выходе.


## Вход

При запуске приложение проверяет `GET /api/auth/session`. После входа или выхода
селектор заново запрашивает доступные сервисы. Публичные сервисы и Mock Customer
API доступны анонимно. Приватные сервисы требуют учётной записи и выдачи доступа
администратором. Самостоятельной регистрации нет.

Для входа в production откройте frontend на `https://graphql.rebyte.fun/coverage/`,
чтобы Origin совпал с настройкой backend. Прокси Vite к production подходит для
анонимного чтения. Для проверки входа через Vite используйте локальный backend и
его настройки Origin, указанные выше.
