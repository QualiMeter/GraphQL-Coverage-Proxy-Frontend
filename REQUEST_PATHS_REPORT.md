# Пути GraphQL-запросов — отчёт

Реализация оставлена локально на `feat/frontend-dashboard`. Предыдущие изменения Mock-очистки, сравнения прогонов и GitLab CI сохранены. Коммитов, операций записи в GitHub, изменений backend/QA, GitLab, CI/CD или production не выполнялось.

## Реализация

В существующие подробности поля добавлен раскрывающийся блок «Пути обращения к полю». GET `/api/runs/{runId}/paths` выполняется только после раскрытия, с конечным полем, limit=50 и серверным offset. Для цепочки показываются полный список координат, глубина и pathHits. Следующие страницы загружаются по «Показать ещё». Доступность available/partial/unavailable не смешивается с нулевым покрытием.

Кнопка найденного пути переводит в существующий журнал, сохраняя сервис через текущий scope, snapshotId, runId, конечное поле и цепочку координат. Временный режим использует ту же таблицу, те же строки и прежнюю панель подробностей обращения с CodeView. Новые страницы, основные вкладки, модальные окна, таблицы обращений и графы не создавались. Дополнительная подсветка графа/кода не добавлялась; существующий layout графа не изменялся.

Поиск читает кандидатов по конечному полю, по 100 записей на шаг. Подробности запрашиваются максимум четырьмя параллельными workers, а следующие страницы — только по действию пользователя. Промежуточные совпадения сразу доступны в таблице. Есть отмена, продолжение, сброс пути, счётчики просмотренных, подтверждённых, непроверенных, несовпавших и оставшихся кандидатов. Непроверенные обращения можно раскрыть и открыть в той же панели подробностей. Обычные фильтры на время поиска приостановлены и возвращаются после сброса пути; конечное поле сохраняется как обычный фильтр.

Подробности кэшируются в рамках текущего поиска (до 200 записей и примерно 2 млн символов документов); повторяющиеся документы также имеют ограниченный кэш решений. При открытии результата используются уже прочитанные реальные подробности, если они ещё находятся в кэше. После вытеснения подробности повторно читаются существующим клиентом.

Смена сервиса/сессии, снимка, прогона, поля и выход из режима отменяют запросы либо изолируют прежний результат по ключу контекста. Поздние ответы отменённого шага игнорируются. Отмена сохраняет уже проверенную часть; продолжение дорабатывает текущую порцию без повторной проверки завершённых кандидатов. Сброс уничтожает сессию поиска и её кэши.

## AST и ограничения достоверности

Переиспользована существующая зависимость `graphql`, новых зависимостей нет. SDL читается для выбранного snapshot и строится один раз на сессию поиска. Документ разбирается и сопоставляется со схемой через AST, а не подстроки. Учитываются aliases, вложенность, named/inline fragments, повторное использование fragments, корневой тип и metadata operationName/operationType при нескольких операциях.

Результат имеет три состояния: подтверждённая цепочка, отсутствие цепочки в проверенном документе и непроверенное обращение. Недоступный документ, ошибки разбора/схемы, неизвестная выбранная операция, неоднозначный абстрактный владелец поля и неизвестные условия не превращаются в доказанное отсутствие. `selectedFields` не используется для восстановления документа.

Конкретный тип, явно заданный фрагментом, позволяет сопоставить координату документа; конкретный runtime-тип из абстрактного интерфейса/union не выдумывается. Переменные условных директив не разрешаются без фактических значений. У redacted-документов литералы условий также считаются неизвестными. Для обычных аргументов маскировка значений не мешает структурной проверке пути; правило проверки типов самих литералов исключено, остальные правила GraphQL-валидации сохраняются. Разбор/обход ограничен безопасным объёмом; превышение даёт «непроверено».

Подтверждение относится к наличию цепочки в сохранённом документе, а не выполнению resolver и не наблюдению поля в ответе. pathHits и coverage hits не приравниваются. Число найденных документов не подгоняется под pathHits.

Кандидаты по конечному полю ограничены данными backend об успешном выборе поля. Исторические обращения без доступной информации о выбранных координатах могут вообще не попасть в этот список. Отсутствие документов/неизвестные директивы и консервативное сопоставление типов также ограничивают полноту. Offset-пагинация пополняющегося журнала не даёт транзакционного снимка: оставшееся число оценивается по последнему X-Total-Count, дубли исключаются, но абсолютная полнота на активном прогоне не заявляется.

Ошибки API и 401/403 сохраняют свои сообщения, а не подменяются успешным пустым поиском. Если SDL не прочитан из-за API-ошибки, поиск останавливается с возможностью повтора; если полученный SDL невозможно построить, проверенные кандидаты помечаются непроверенными. Неудачное чтение отдельных подробностей также не считается отсутствием пути.

## Проверки

- `npm run lint`: успешно.
- `npm test`: 30 файлов, 284 теста успешно; добавлено 39 тестов.
- `npm run build`: успешно. Сохраняется предупреждение Vite о JS-файле больше 500 kB; дополнительная GraphQL-валидация увеличила bundle.
- `git diff --check`: успешно.

Браузер на реальном backend: открыты существующая схема Product и поле Product.price, проверено наличие свёрнутого блока и его раскрытие. Реальный `/paths` вернул unavailable — показано сообщение о недоступных данных без ложного нуля. У анонимного пользователя доступ к журналу отсутствует, поиск не предлагается как доступное действие.

Сквозной браузерный поиск заполненного журнала, открытие реального совпадения и API-пагинация на объёме больше 100 кандидатов не проверены: в доступном прогоне нет путей и отсутствует авторизованная сессия с правами на журнал. Корректность соответствующих алгоритмов и интерфейсных контрактов проверена автоматическими тестами; полный браузерный регресс не заявляется. Реальные обращения, прогоны и pipeline ради тестирования не создавались.
